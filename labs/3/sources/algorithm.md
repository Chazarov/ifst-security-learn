# Основы алгоритма RSA

RSA — алгоритм **асимметричного** шифрования: есть два связанных ключа. То, что зашифровано одним, расшифровывается только другим. Секрет распределён: один ключ можно отдавать всем, второй хранить у себя.


## Симметричное и асимметричное (связь с lab 2)

| | Симметричное (AES, DES) | Асимметричное (RSA) |
|---|---|---|
| Ключи | Один общий секретный ключ | Пара: открытый + закрытый |
| Скорость | Быстро, подходит для файлов и потоков | Медленно, только для коротких данных |
| Обмен ключами | Нужно передать ключ безопасно | Открытый ключ можно публиковать |
| Типичное применение | Шифрование данных | Обмен ключами, подписи, короткие сообщения |

На практике почти всегда **гибрид**: RSA передаёт короткий ключ AES, а AES шифрует основной объём (файл, канал TLS и т.д.).


## Роли ключей

**Открытый ключ** $(e, n)$ — можно знать всем.

**Закрытый ключ** $(d, n)$ — только владелец.

Шифрование конфиденциальности:

- шифруют **открытым ключом получателя** → расшифровывает только он **закрытым**
- формула: $C = M^e \bmod n$ (открытый), $M = C^d \bmod n$ (закрытый)

Цифровая подпись (другая операция, те же ключи):

- подписывают **закрытым ключом отправителя** → проверяют **открытым**
- на практике подписывают не весь файл, а хеш: $S = H(M)^d \bmod n$, проверка $H(M) \stackrel{?}{=} S^e \bmod n$

Путаница, которую стоит избегать: «закрытый ключ всегда для расшифровки» — нет, для **подписи** он для **создания** подписи, а расшифровывает тот, у кого открытый ключ проверки (у отправителя).


## Пошаговый алгоритм


### Шаг 1. Генерация ключей

Выбираем два больших простых числа $p$ и $q$. В учебном примере — маленькие:

$$p = 3, \quad q = 11$$

Модуль (часть обоих ключей):

$$n = p \cdot q = 33$$

Функция Эйлера:

$$\varphi(n) = (p - 1)(q - 1) = 20$$

Открытая экспонента $e$:

- $1 < e < \varphi(n)$
- $\gcd(e, \varphi(n)) = 1$ — иначе обратный $d$ не существует

Почему нужна взаимная простота: если $\gcd(e, \varphi(n)) > 1$, уравнение $de \equiv 1 \pmod{\varphi(n)}$ не имеет решения, и расшифровка невозможна. Обычно берут $e = 65537$ — простое и быстрое для возведения в степень.

В примере: $e = 3$, $\gcd(3, 20) = 1$.

Закрытая экспонента $d$ — число, для которого:

$$d \cdot e \equiv 1 \pmod{\varphi(n)}$$

В примере: $d = 7$, так как $3 \cdot 7 = 21 \equiv 1 \pmod{20}$.

Результат:

- открытый ключ: $(e, n) = (3, 33)$
- закрытый ключ: $(d, n) = (7, 33)$

Секретность RSA держится на том, что из известного $n$ практически нельзя восстановить $p$, $q$ и затем $d$.


### Как найти $d$ на практике (расширенный алгоритм Евклида)

Подбором подходит только для учебных чисел. Для реальных ключей $d$ вычисляют **расширенным алгоритмом Евклида**: находят $x, y$ такие, что

$$e \cdot x + \varphi(n) \cdot y = \gcd(e, \varphi(n)) = 1$$

Тогда $d = x \bmod \varphi(n)$ (если $x$ отрицательный — прибавляют $\varphi(n)$).

Библиотеки (PyCryptodome, OpenSSL) делают это автоматически при `RSA.generate()`.


### Шаг 2. Шифрование

Алиса шифрует $M = 2$ **открытым ключом Боба** $(3, 33)$:

$$C = M^e \bmod n = 2^3 \bmod 33 = 8$$

Боб единственный, кто может получить $M$ обратно — у него $(d, n)$.


### Шаг 3. Расшифрование

$$M = C^d \bmod n$$

Быстрое возведение в степень для $8^7 \bmod 33$:

$$8^2 \equiv 31, \quad 8^4 \equiv 4, \quad 8^6 \equiv 25, \quad 8^7 \equiv 2 \pmod{33}$$

Получили $M = 2$.


## Ограничения на сообщение $M$

В «голом» RSA сообщение — это **целое число**:

$$0 \le M < n$$

Если $M \ge n$, его сначала делят на блоки или используют другую схему. Для ключа 2048 бит модуль $n$ — около 256 байт, значит **за один раз RSA шифрует не больше ~190–214 байт** (с учётом padding).

Текст и файлы нельзя подставить в формулу напрямую: байты превращают в число, а большие файлы **режут на блоки** (как в lab 3) или не шифруют RSA целиком, а только симметричный ключ.


## Почему это работает

По построению $de = 1 + k\varphi(n)$, поэтому:

$$C^d \equiv M^{ed} \equiv M^{1 + k\varphi(n)} \pmod{n}$$

**Теорема Эйлера:** если $\gcd(M, n) = 1$, то $M^{\varphi(n)} \equiv 1 \pmod{n}$, откуда $C^d \equiv M$.

**Краевой случай:** если $\gcd(M, n) \neq 1$ (редко при случайном $M$ и больших простых $p, q$), классическое доказательство через Эйлера не применяется напрямую. На практике:

- $p$, $q$ огромные, случайные $M$ почти всегда взаимно просты с $n$
- **padding (OAEP)** превращает данные в псевдослучайный блок, где такие совпадения не эксплуатируются
- иногда используют **китайскую теорему об остатках (CRT)** для ускорения расшифровки через $p$ и $q$ отдельно

Для сдачи lab 3 достаточно помнить: корректность RSA математически доказана для правильно выбранных $p, q, e, d$; в коде за безопасное представление $M$ отвечает OAEP, а не ручная подстановка в $M^e \bmod n$.


## Цифровая подпись

Подпись доказывает, что сообщение создал владелец **закрытого** ключа, а не подделал кто-то другой.

1. Вычисляют хеш: $h = H(M)$ (SHA-256 и т.д.)
2. Подпись: $S = h^d \bmod n$ (закрытым ключом)
3. Проверка: вычисляют $h' = S^e \bmod n$ и сравнивают $h' \stackrel{?}{=} H(M)$

Шифрование и подпись — **разные цели**: первое прячет содержимое от чужих, второе доказывает авторство и целостность. В lab 3 реализовано шифрование файлов; подпись — отдельная тема, но математика та же (степени $e$ и $d$).


## Padding и OAEP

**Проблема без padding:** одно и то же $M$ всегда даёт одно и то же $C$. Атакующий может угадать сообщение по словарю или сравнить шифротексты.

**Проблема малого $e$:** при $e = 3$ и нескольких сообщениях с малым $M$ возможны атаки без факторизации $n$.

**OAEP (Optimal Asymmetric Encryption Padding)** перед шифрованием:

- добавляет случайные байты
- смешивает данные с хешем
- на выходе получается блок фиксированного размера, готовый к $M^e \bmod n$

В lab 3 используется `PKCS1_OAEP` — это **не** формула из учебного примера $C = M^e \bmod n$, а стандартная обёртка вокруг RSA. Поэтому в программе шифрование безопаснее, чем «голый» RSA из раздела с $M = 2$.


## Гибридное шифрование

RSA не шифруют гигабайтные файлы целиком — это медленно и неудобно по размеру блока.

Схема:

1. Генерируют случайный симметричный ключ $K$ (AES)
2. $C_K = \text{AES}_K(\text{файл})$
3. $C_{\text{rsa}} = \text{RSA}_{\text{открытый}}(K)$
4. Передают $C_{\text{rsa}}$ и $C_K$

Получатель расшифровывает $K$ закрытым RSA-ключом, затем файл — AES. В lab 3 для задания достаточно **прямого** RSA по блокам файла; в реальных системах (HTTPS, почта) почти всегда гибрид.


## Безопасность и угрозы

**Основа стойкости:** сложность **факторизации** $n = p \cdot q$. Зная $p$ и $q$, легко найти $\varphi(n)$ и $d$.

**Рекомендуемые размеры:**

| Размер $n$ | Уровень (ориентир) |
|---|---|
| 2048 бит | Минимум для новых систем |
| 3072–4096 бит | Повышенные требования |

**Слабые места:**

- слишком малые $p$, $q$ или близкие друг к другу — факторизация проще
- один и тот же $n$ с разными партнёрами без нужды — риск
- хранение закрытого ключа в открытом XML на диске — утечка ключа = полная компрометация
- шифрование без OAEP — утечки по повторам и структуре данных

**Что RSA не даёт сам по себе:** целостность и защита от подмены канала — для этого нужны подписи, MAC или TLS.


## Форматы ключей

**Учебный XML (lab 3):**

- открытый: `<RSAKeyValue><Modulus>...</Modulus><Exponent>...</Exponent>`
- закрытый: `<RSAKeyValue><PrivateKey>...</PrivateKey>`

Данные в base64. В программе экспорт/импорт через диалог выбора файла.

**В реальных системах чаще:**

- **PEM** — текстовый файл с заголовками `-----BEGIN PUBLIC KEY-----`
- **DER** — бинарное представление того же ключа
- **PKCS#8** — формат закрытого ключа

Смысл тот же: сохранить $n$, $e$ или полную пару $(n, e, d, p, q, \ldots)$. XML в lab 3 — способ выполнить требование задания «файлы формата XML», не единственный стандарт в индустрии.


## Связь с лабораторной работой 3

| Требование задания | Что происходит в коде |
|---|---|
| Генерация пары RSA | `RSA.generate(2048)` — случайные $p$, $q$, вычисление $n$, $e$, $d$ |
| Экспорт/импорт XML | `export_*_key_xml`, `import_*_key_xml` + диалог файла |
| Шифрование файла | Открытый ключ + `PKCS1_OAEP`, файл читается блоками |
| Расшифрование файла | Закрытый ключ + OAEP, блоки склеиваются |

**Почему блоки:** размер одного RSA-блока с OAEP для 2048 бит:

$$\text{макс. байт} \approx \frac{2048}{8} - 42 = 214$$

Файл больше — режут на куски; перед каждым блоком в `.enc` пишут длину (4 байта), затем шифротекст блока.

**Почему не формула из примера:** в `core.py` не вызывают вручную $M^e \bmod n$ для текста «Привет» — библиотека применяет OAEP и бинарное возведение в степень. Математика RSA та же, представление данных — промышленное.


## Краткая шпаргалка

Генерация: $n = pq$, $\varphi(n) = (p-1)(q-1)$, выбрать $e$, найти $d$ через $de \equiv 1 \pmod{\varphi(n)}$.

Шифрование (конфиденциальность): $C = M^e \bmod n$ открытым ключом получателя.

Расшифрование: $M = C^d \bmod n$ закрытым ключом получателя.

Подпись: $S = H(M)^d \bmod n$; проверка: $S^e \bmod n \stackrel{?}{=} H(M)$.

Практика: большие $p,q$; OAEP; файлы — блоками или гибрид с AES; закрытый ключ не публиковать.
